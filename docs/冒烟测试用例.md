# 轻阅读（YueduPC）冒烟测试用例

> 用途：每次改动代码后，按本用例快速回归核心链路，确认没有破坏既有功能。
> 适用版本：WinUI 3 + .NET 8，unpackaged 自包含 x64。
> 维护：新增功能或修复后，把对应的验证步骤补充进本文档。

---

## 0. 测试前置（构建与部署）

| 编号 | 步骤 | 预期结果 |
|------|------|----------|
| S0-1 | 执行 Debug + Release 双构建：`/c/Program Files/dotnet/dotnet.exe build -c Release -r win-x64`（Debug 同理） | 两套构建均 **0 错误 0 警告（无新增警告）**；若怀疑 XAML 生成缓存问题，先清理 `obj` 再重建 |
| S0-2 | 将最新构建**完整同步**到桌面快捷方式指向的运行目录 `bin/x64/Release/net8.0-windows10.0.19041.0/` | 同步内容必须包含：`QingYueDu.dll/exe/pdb` + **`Views/*.xbf`、`App.xbf`、`MainWindow.xbf`、`*.pri`** + `Assets/pdfjs`。只复制 dll/exe 会导致连接 ID 与旧 xbf 错位，`ReaderPage.Connect` 抛 `Unable to cast IInspectable to Border` 直接崩进程 |
| S0-3 | 若 exe 被占用，先 `Stop-Process -Name QingYueDu -Force`，再启动 | 无残留进程，可正常启动 |

| 编号 | 步骤 | 预期结果 |

## 7. 回归专项：「所有书打不开 / 无正文」检查清单

> 背景：2026-11-26 曾出现「斗破苍穹打开没正文 → 所有书都打不开」的全局回归。
> 根因四连：① XAML 解析期 `BrightnessSlider` 从 0 矫正到 30 触发 ValueChanged，提前初始化 WebView2；② OnNavigatedTo 预热 Core 导致永久挂起；③ `Changed` 事件异常使书库加载 Task 被永久缓存为失败；④ 构建同步漏了 `.xbf`/`.pri` 导致 XAML 连接错位崩溃。
> 以下用例用于防止同类问题再次发生。

| 编号 | 检查点 | 预期结果 |
|------|--------|----------|
| R-1 | `ReaderPage.xaml.cs` 中 `_flyoutInit` 初值 | **必须为 `true`**，`OnNavigatedTo` 末尾置 `false`（保证 XAML 解析期滑块事件被拦截） |
| R-2 | `ReaderPage.OnNavigatedTo` 中**不得**有 Core 预热调用 | 不存在 `await EnsureCoreAsync()` 之类在导航期预热的代码；Core 由 `DocumentRebuildRequested → ReloadDocumentAsync` 在页面显示后自然初始化 |
| R-3 | `EnsureCoreInnerAsync` 初始化 WebView2 Core | 有 15 秒超时兜底；失败时记录日志并显示「正文渲染组件初始化失败」提示层，**不得无提示白屏** |
| R-4 | `LibraryService.LoadAsync` | 使用 Task 缓存（`_loadTask ??= LoadInnerAsync()`），faulted 时允许重建；**不得**用 `if(_loaded)return; _loaded=true;` 在异步读文件前置位（并发调用会拿到空书库） |
| R-5 | `LibraryService` 的 `Changed` 事件派发 | 通过 `RaiseChanged()` **逐个订阅者 try-catch**，订阅者异常不得污染加载 Task |
| R-6 | ViewModel → View 的异步回调 | 统一走 `SafeUi(Func<Task>)`（检查 `_unloaded` + try-catch），页面卸载后回调不崩进程 |
| R-7 | 构建同步产物 | 除 dll/exe/pdb 外，**必须**包含 `Views/*.xbf`、`App.xbf`、`MainWindow.xbf`、`*.pri`、`Assets/pdfjs`（见 S0-2） |
| R-8 | 打开任意书（本地 TXT/EPUB、在线书、PDF 各一本） | 正文均正常显示，无空白、无「本章加载失败」、无闪退 |
